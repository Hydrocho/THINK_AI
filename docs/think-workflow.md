# THINK 활동 저장 및 운영

## 구현 경로

- `js/modules/thinkWorkflow.js`: 실제 학생 화면, 저장 큐, 재입장 복원, 단계 상태 확인.
- `supabase/functions/think-workflow/index.ts`: 인증, 교사 조회, AI 호출.
- `supabase/migrations/20261111000000_think_workflow.sql`: 학급별 기록·익명 배정·AI 대화 및 원자적 저장 RPC.
- 기존 교사 학생별 글 화면은 새 API를 이용한다. H에서 ‘친구 의견 배정’, 모든 단계에서 ‘기록 새로고침’을 제공한다.
- 기존 `studentThink.js`와 `app.js`의 구형 저장 핸들러는 신규 모듈이 실제 화면 경로를 대체한다. 신규 모듈은 `app.js` 다음에 로드한다.

## 저장 정책

작성 가능 상태에서 단계에 입장하면 서버가 작성 토큰을 발급한다. 4초 간격으로 교사의 단계 상태를 확인하고, 마감 감지 시 입력을 잠그고 마지막 버퍼를 서버에 저장한다. 마감 전에 시작된 자동 저장이 늦게 도착하는 경우도 허용하며, 마지막 저장을 확인한 토큰으로는 더 저장할 수 없다. 닫힌 상태에서 새 토큰은 발급하지 않는다.

저장은 단계별 큐와 서버 revision 검사로 순서를 보장한다. 응답 유실 시 같은 request ID로 재시도한다. 다른 탭의 저장과 충돌하면 자동 덮어쓰기하지 않고 글 보존·재입장을 안내한다. 미저장 글은 같은 탭의 sessionStorage에도 보관하며, 다른 저장본과 충돌하면 복사할 수 있도록 따로 표시한다. 로그아웃은 저장 성공 후 화면과 임시 저장을 정리한다.

## 익명 의견과 AI

교사가 배정 버튼을 누르면 같은 학급의 제출된 T 답변에서 본인을 제외하고 최대 4개를 스냅샷으로 저장한다. 최초 배정이 비어 있었다면 다시 배정할 수 있으나, 비어 있지 않은 기존 배정은 바뀌지 않는다. 학생에게는 원 작성자의 ID·학번·이름을 전송하지 않는다.

AI는 서버가 DB에서 조회한 핵심 질문과 응답 모드를 사용한다. 성공·실패·처리 중 상태를 저장하고 실패는 질문 횟수에서 제외한다. 서버 예약과 요청 ID로 중복 과금을 막는다. 120초를 넘긴 미완료 요청은 다음 조회 때 실패 처리하며, 오래된 실행의 응답이 새 시도를 덮어쓰지 않도록 attempt ID를 확인한다. 마감 전에 접수된 AI 응답은 마감 후에도 저장한다.

## 검증 및 배포

`npm ci` 후 `npm run test:workflow`를 실행한다. PostgreSQL 호환 PGlite로 마감·권한·revision·배정·질문 한도를 검증하고, DOM 기반 학생 화면 검사로 복원·마감 중 저장·재시도·차시 전환을 검증한다.

배포 순서:
1. DB 마이그레이션 적용 및 이력 등록 (다른 미적용 마이그레이션을 무조건 함께 적용하지 않는다).
2. `think-workflow` 함수 배포 (`--no-verify-jwt`; 함수 내부에서 `auth.getUser`로 인증).
3. `analyze-teacher-stage-responses` 배포 (새 학급별 저장소 사용).
4. 서버 통합 확인 후 정적 사이트 배포.

필요한 토큰 범위: 해당 프로젝트의 Database/Migrations 및 Edge Functions 읽기·쓰기. AI 함수에는 기존 `GEMINI_API_KEY`, 선택적으로 `GEMINI_CHAT_MODEL`이 필요하다. 키 값을 클라이언트 또는 로그로 출력하지 않는다.
