# 학생 초기 비밀번호 및 변경 강제 설계

## 목적

새로 생성하거나 교사가 비밀번호를 초기화한 학생 계정은 초기 비밀번호 `000000`으로만 로그인할 수 있게 한다. 해당 학생은 수업 화면에 들어가기 전에 반드시 새 비밀번호를 설정해야 한다.

## 범위

- 새 학생 계정 생성 시 초기 비밀번호는 항상 `000000`이다.
- 교사의 비밀번호 초기화는 별도 비밀번호 입력 없이 항상 `000000`으로 재설정한다.
- 새로 생성되거나 초기화된 학생만 `must_change_password = true` 상태가 된다.
- 이미 존재하는 학생 계정의 비밀번호나 상태는 변경하지 않는다.
- 새 비밀번호는 6자 이상이어야 하며 `000000`은 허용하지 않는다. (Supabase Auth 최소 길이)

## 데이터 및 권한

`student_accounts`에 `must_change_password boolean not null default false` 열을 추가한다. 교사 전용 학생 관리 Edge Function만 이 상태를 생성 및 초기화 시 `true`로 설정한다.

학생은 로그인 후 전용 Edge Function을 호출해 자신의 비밀번호를 바꾸며, 함수는 JWT의 사용자 ID가 자신의 학생 계정과 일치하는지 확인한다. 검증 성공 후 Supabase Auth 비밀번호를 변경하고, 해당 계정의 `must_change_password`를 `false`로 바꾼다. 서비스 역할 키는 Edge Function 내부에만 둔다.

## 화면 흐름

1. 학생이 학번과 비밀번호로 로그인한다.
2. 학생 계정의 `must_change_password`가 `true`이면 비밀번호 변경 화면을 표시한다.
3. 변경 완료 전에는 학생 로비 및 수업 기능을 표시하지 않는다.
4. 유효한 새 비밀번호로 변경되면 학생 로비로 이동한다.

## 오류 처리

- 6자 미만 또는 `000000` 입력 시 변경 요청 전에 안내한다.
- Edge Function도 동일 규칙을 검사해 클라이언트 우회를 막는다.
- 권한이 없거나 학생 계정과 JWT가 일치하지 않으면 변경을 거부한다.
- Auth 변경 또는 상태 변경 실패 시 성공 화면으로 이동하지 않고 오류를 표시한다.

## 검증

- 비밀번호 규칙 검증 함수를 단위 테스트한다.
- 새 계정 생성 및 초기화 요청이 `000000`과 변경 필요 상태를 설정하는지 코드 수준에서 검증한다.
- 로그인 뒤 변경 필요 학생이 로비 대신 변경 화면으로 가는 흐름을 수동 확인한다.
